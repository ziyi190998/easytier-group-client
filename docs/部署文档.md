## 二、腾讯云 IP 分配服务

### 接口（全部 HTTPS，自签证书指纹固定在客户端内）
| 接口 | 说明 |
|---|---|
| `POST /api/alloc` `{"invite_code":...}` | 分配虚拟IP，返回 `{ip, network_name, network_secret, peer_urls, heartbeat_interval_sec}`；同码幂等 |
| `POST /api/heartbeat` `{"invite_code","ip"}` | 续期；失配返回 409 |
| `POST /api/release` | 释放 |
| `GET /api/health` | 健康检查（无鉴权） |
| `GET /api/status?admin_key=密钥` | 池占用/邀请码状态（脱敏输出） |
| `POST /api/admin/reload`（Header `X-Admin-Key`） | 修改 codes.json 后热重载 |

心跳 TTL 90 秒：客户端每 30 秒心跳，连续 3 次失败或进程退出后 90 秒，服务端自动回收 IP。

### 日常运维（SSH 到腾讯云）
```bash
ssh -i astrbot.pem ubuntu@101.43.121.186
cd ~/easytier-ip-alloc

# 查看池占用（ADMIN_KEY 在服务器 .env 内，不出服务器）
curl -sk "https://127.0.0.1:11020/api/status?admin_key=$(grep ADMIN_KEY .env | cut -d= -f2)"

# 容器日志
sudo docker logs --tail 50 easytier-ip-alloc

# 重启 / 更新代码后重建
sudo docker compose restart
sudo docker compose up -d --build
```

### 密钥位置（全部只在服务器上，不入仓库）
- `~/easytier-ip-alloc/.env`：NETWORK_NAME / NETWORK_SECRET / ADMIN_KEY（600 权限）
- `~/easytier-ip-alloc/data/codes.json`：10 个邀请码（600 权限）
- `~/easytier-ip-alloc/data/server.pem|key`：自签证书（指纹已被客户端固定）

### 邀请码管理
```bash
# 查看全部邀请码
sudo cat ~/easytier-ip-alloc/data/codes.json

# 新增/吊销：编辑后热重载（revoked=true 即吊销）
vi ~/easytier-ip-alloc/data/codes.json
curl -sk -X POST -H "X-Admin-Key: $(grep ADMIN_KEY ~/easytier-ip-alloc/.env | cut -d= -f2)" https://127.0.0.1:11020/api/admin/reload
```
生成新码：`openssl rand -hex 8`。一格一码发给一位群友，泄露只吊销该码。

### 口令轮换（谨慎，会断所有连接）
1. 修改腾讯云与璐璐娅两个 easytier 节点的 `--network-secret` 并重启节点；
2. 修改腾讯云 `.env` 的 `NETWORK_SECRET`，`docker compose restart`；
3. 群友客户端重连即自动换取新口令（客户端不含口令，无需更新 exe）。
4. 证书轮换：删除 `data/server.pem|key` 重启容器生成新证书，但**需同步更新客户端内置指纹**（重新发布 exe），非必要不轮换。

### 安全组
- 已放行：11010~11013（easytier）、11020/tcp（IP 分配服务，实测已通）。
- 若换端口：同步改 compose 的 ports、安全组、以及客户端 `ClientConfig.ServiceUrl` 默认值。

## 三、璐璐娅服务器（VM100 / Arch Linux）

### 群友入站白名单（已部署）
- 规则文件 `/etc/easytier-guest.nft`，systemd 服务 `easytier-guest-firewall`（开机自启）。
- 作用域**仅 tun0 网卡 + 群友网段 10.144.0.100~109**：放行 ICMP 与已建立连接，丢弃其它新建入站；局域网 SSH/物理网卡/中继完全不受影响，无自锁风险。
- **开服放行端口**：编辑 `/etc/easytier-guest.nft`，在「放行端口模板」区取消注释/添加，然后：
  ```bash
  systemctl restart easytier-guest-firewall   # 重载规则
  nft list table inet easytier_guest          # 查看当前规则
  ```
- 仓库对应源文件：`server-luluya/easytier-guest.nft`、`server-luluya/easytier-guest-firewall.service`。

### 群友互访隔离（客户端侧，自动）
连接时客户端自动添加两条 Windows 防火墙规则（阻止与 10.144.0.100~109 双向通信，保留访问 .1/.254），断开自动移除。EasyTier 开源版无对端级 ACL（P2P 直连无法在服务端拦截），此为客户端侧兜底；如需强隔离需后续升级 EasyTier Secure Mode。

### 可选：单群友限速（未启用）
如需限制单个群友带宽，在 VM100 的 nft 表中追加（以 20Mbps 为例）：
```
iifname "tun0" ip saddr 10.144.0.100-10.144.0.109 limit rate 20 mbit/second accept
```

## 四、客户端构建与发布

前置：.NET 8 SDK（Windows Desktop 负载）；`tools/easytier/easytier-windows-x86_64/` 下有 easytier 2.6.4 五件套（easytier-core.exe / easytier-cli.exe / wintun.dll / Packet.dll / WinDivert64.sys，可从 `easytier-windows-x86_64-v2.6.4.zip` 解压，下载走代理 `http://127.0.0.1:7890`）。

```bash
dotnet publish client/EasyTierGroupClient/EasyTierGroupClient.csproj -c Release -r win-x64 \
  --self-contained true -p:PublishSingleFile=true \
  -p:EnableCompressionInSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true \
  -o publish/
cp publish/EasyTierGroupClient.exe "publish/EasyTier群友客户端.exe"
```

要点：
- 内嵌 easytier 组件，首启自解压到 `%LOCALAPPDATA%\EasyTierGroupClient\bin\`；
- 需管理员运行（wintun 驱动 + 防火墙规则），已内置 UAC 清单；
- TLS 证书指纹固定在 `ClientConfig.CertSha256`（换证书必须重发）；
- 口令/邀请码不落盘、不进日志（仅邀请码存本机 `%APPDATA%` 供自动连接）。

客户端日志：`%LOCALAPPDATA%\EasyTierGroupClient\logs\`（client.log + easytier 文件日志）。

## 五、故障排查速查

| 现象 | 处理 |
|---|---|
| 群友连接后 ping 不通 10.144.0.1 | 看 VM100 `nft list table inet easytier_guest` 是否误加 drop；看 easytier 路由 `easytier-cli route` |
| 提示「邀请码无效」 | 服务器 codes.json 是否吊销/输错；改完记得 `/api/admin/reload` |
| 提示「人数已满」 | `/api/status` 看占用；僵尸租约 90 秒后自动回收 |
| 全员连不上分配服务 | 腾讯云安全组 11020；`docker ps` 看容器健康；`docker logs easytier-ip-alloc` |
| 客户端组件启动失败 | 首次运行的驱动弹窗没允许；删 `%LOCALAPPDATA%\EasyTierGroupClient\bin` 后重试 |
| 服务器维护需断开群友 | `sudo docker compose stop`（IP 服务停了客户端会持续重试，恢复后自动重连） |
